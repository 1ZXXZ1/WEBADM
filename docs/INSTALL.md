# Установка и первый запуск

## Системные требования

| Компонент | Минимальная версия |
|-----------|-------------------|
| Node.js | 18.x или выше |
| npm / bun | npm 8.x+ / bun 1.x+ |
| Python | 3.9+ (для бэкенда) |
| PostgreSQL | 12+ (для бэкенда) |
| Samba AD DC | 4.15+ (на сервере) |

## Шаг 1: Клонирование и установка зависимостей

```bash
# Клонировать репозиторий
git clone <repository-url>
cd web_project

# Установить зависимости
npm install
# или
bun install
```

## Шаг 2: Настройка переменных окружения

Создайте файл `.env` в корне проекта (или используйте существующий):

```env
# База данных SQLite (для локальных настроек фронтенда)
DATABASE_URL=file:/custom.db

# URL бэкенда Samba AD DC Management API
# Это Python/FastAPI сервер, с которым общается фронтенд
# API-прокси в Next.js (/api/v1/*) перенаправляет запросы на этот адрес
SAMBA_API_URL=http://localhost:8080/api/v1
```

### Описание переменных

| Переменная | Обязательная | По умолчанию | Описание |
|------------|-------------|-------------|----------|
| `DATABASE_URL` | Нет | `file:/custom.db` | URL базы данных SQLite для Prisma |
| `SAMBA_API_URL` | Нет | `http://localhost:8080/api/v1` | URL Python/FastAPI бэкенда для API-прокси |

## Шаг 3: Инициализация базы данных

```bash
# Сгенерировать Prisma клиент
npx prisma generate

# Применить схему к базе данных
npx prisma db push
```

> **Примечание:** База данных SQLite используется только для хранения локальных настроек фронтенда (модели User и Post — шаблонные). Все данные Active Directory приходят из Python/FastAPI бэкенда.

## Шаг 4: Настройка Python/FastAPI бэкенда

Фронтенд не работает автономно — ему необходим запущенный Python-бэкенд (Samba AD DC Management API). Убедитесь, что:

1. Бэкенд запущен и доступен по URL, указанному в `SAMBA_API_URL`
2. Бэкенд подключён к Samba AD DC серверу
3. Бэкенд использует PostgreSQL для хранения пользователей API и ключей

Проверить доступность бэкенда можно запросом:
```bash
curl http://localhost:8080/api/v1/health
```

Ожидаемый ответ:
```json
{
  "status": "ok",
  "version": "2.8",
  "server_role": "active directory domain controller"
}
```

## Шаг 5: Запуск в режиме разработки

```bash
npm run dev
```

Приложение будет доступно по адресу: **http://localhost:3000**

## Шаг 6: Первый вход

На странице авторизации доступны два способа входа:

### Вход по паролю
1. Введите имя пользователя (например, `admin`)
2. Введите пароль
3. Нажмите «Войти»

Система отправит запрос `POST /auth/login` на бэкенд, получит JWT-токены и роль пользователя.

### Вход по API-ключу
1. Переключитесь на вкладку «API Key»
2. Введите API-ключ (формат: `sk-xxxxxxxxxxxx`)
3. Нажмите «Войти»

Система отправит запрос `POST /auth/check` с заголовком `X-API-Key` на бэкенд.

### Настройка URL API (опционально)
Если бэкенд работает не на `localhost:8080`, укажите его URL в поле «API Server URL» внизу формы авторизации (например, `http://192.168.1.100:8080/api/v1`).

## Возможные проблемы

### Ошибка подключения к бэкенду
Если при входе возникает ошибка, проверьте:
1. Запущен ли Python/FastAPI бэкенд
2. Правильный ли URL указан в поле «API Server URL»
3. Доступен ли бэкенд по сети (нет ли блокировки фаерволом)
4. Правильно ли указана переменная `SAMBA_API_URL` в `.env`

### Ошибка CORS
Если бэкенд возвращает ошибки CORS, убедитесь, что на бэкенде настроены заголовки:
```
Access-Control-Allow-Origin: http://localhost:3000
Access-Control-Allow-Headers: Authorization, X-API-Key, Content-Type
```

> **Примечание:** При использовании API-прокси Next.js (`/api/v1/*`) CORS не является проблемой, так как запросы идут через серверную часть Next.js.

### Пустая страница после входа
Если после входа страница пустая, проверьте:
1. Получены ли права (permissions) от бэкенда
2. Открыта ли консоль браузера (F12) на наличие ошибок
3. Доступен ли API-эндпоинт `/dashboard/overview`
